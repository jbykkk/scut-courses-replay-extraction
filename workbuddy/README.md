# 在 WorkBuddy 中用 SCUT 学习助手

用一句话查课堂出处、接着上次学，或拿课件和论文对照课堂说法。学习目标、实际作答和自评保存在本机；WorkBuddy 按需读取相关片段，用自己的模型讲解和提问，不再套一遍 DeepSeek。

当前版本 **0.5.0 / 20个工具**。流程与记忆设计见 [WorkBuddy Agent 设计](../planning/WORKBUDDY_AGENT.md)，技能入口是 [SKILL.md](skills/scut-study/SKILL.md)。

## 本机接入

先在学习助手里导入至少一门课的字幕或资料，再在项目目录运行一次：

```powershell
.\.venv\Scripts\python.exe scripts\prepare_workbuddy.py --install
```

安装版将 Python 换为 `runtime\python.exe`。自定义资料目录时加 `--data-dir "实际资料目录"`。

脚本把 `scut-study` 合并到 `%USERPROFILE%\.workbuddy\mcp.json`，把技能及 `references/` 规程一起安装到 `skills/scut-study/`。已有连接器保留，变更文件先备份；遇到同名的其他程序会停下，不覆盖。生成文件含本机路径，保存在数据目录的 `workbuddy/`，不要提交 GitHub。

在 WorkBuddy 的“专家·技能·连接器 → 连接器 → 自定义”检查 `scut-study`。客户端尚未加载时，用“添加 MCP”的 JSON 编辑器检查并保存生成的配置。如果出现信任或权限提示，请自己核对后操作。文件已写入不代表客户端已连接，最终应看到 **20 个工具**，且连接检查返回 **0.5.0**。旧会话仍显示10个工具时，重新连接该连接器，再新开对话加载技能，不用重启正在录音的扩展或课堂服务。

新建对话后可以这样说：

> 使用 SCUT 学习助手，检查连接。

> 从头讲神经科学，概念旁写英文，讲清不同模型的联系。每次先讲一部分，再让我做一道题。

> 接着上次的进度，先问我上次没弄清的地方。

> 操作系统老师在哪讲过条件变量？给我原句和回看位置。

> 今晚只有30分钟，先学什么？

> 查公开教材，核对条件变量为什么需要在 while 循环里等待；把课堂说法和教材的适用条件讲清楚。

WorkBuddy 负责启动 MCP 进程。查已有资料时不需要先开学习网页，也不需要重新登录百步梯。新录音和新字幕仍由学习助手导入；工具发现有已保存而未索引的课时，可按课程刷新；回看学校视频时需要在浏览器登录。

## 哪个工具负责什么

| 工具 | 用途 |
| --- | --- |
| `study_connection_status` | 检查资料索引、版本与课程数量 |
| `list_study_courses` | 找到已有课程的名称 |
| `find_classroom_mentions` | 跨课时找原句、课时、时间与回放地址 |
| `search_course_sources` | 搜索本课字幕、教材、题目与外部参考 |
| `read_study_evidence` | 展开一段原文，检查版本和是否停用 |
| `list_confirmed_study_tasks` | 读取已确认且未完成的任务 |
| `plan_today_review` | 在 1–240 分钟预算内排序任务与复习 |
| `search_public_references` | 用公开概念词查论文和教材候选 |
| `read_public_reference` | 读取候选正文或摘要，按问题返回最多三段原文和页码 |
| `prepare_evidence_comparison` | 整理 2–6 段证据的出处、独立性和覆盖范围 |
| `list_course_materials` | 分页查看本课有效资料、版本和片段数量 |
| `prepare_learning_context` | 一次取同课多来源原文、相关确认要求、任务和续接进度 |
| `read_study_evidence_context` | 读取同一版本的前后片段，核对条件与发言转场 |
| `open_learning_session` | 为明确学习目标建立本机会话；重试不重复创建 |
| `get_learning_session` | 恢复目标、最近问题、实际作答及来源失效提示 |
| `list_course_concepts` | 分页查同课、有当前原文支持的术语名称与易混项 |
| `prepare_term_practice` | 打包别名辨认、定义及应用的提问依据 |
| `refresh_course_index` | 同步本课已保存文字，补齐漏索引的课时，不录音 |
| `verify_boolean_design` | 安全解析1–6变量布尔式，穷举逻辑等价并返回反例 |
| `record_learning_progress` | 保存实际作答、可选自评和下一步；版本冲突不覆盖 |

公开检索保存短期缓存，读取参考增加未核验来源；两个学习写入工具只保存目标与学习事件；索引刷新只同步当前课程已保存记录，不修改作业状态、原始字幕或已确认知识。没有通用命令执行、任意文件读取、录音控制、课程批处理或任务完成接口。这些操作继续在本机学习助手进行。调用记录可在学习助手的“运行详情”查看；其中不包含 WorkBuddy 模型内部的思考过程。

## 一次学习怎样继续

先恢复本课已有目标，新目标才建会话。按当前问题取课件、字幕或题目片段，讲清一条概念联系，再出一道题等待回答；后续只记录实际回答，不把示范答案填成学生作答。概念首次引入给英文，说明模型保留、忽略什么以及何时失效。文本、PPT图、板书画面与考试要求分别核对。

学生可自评：1=暂不能解释、2=需提示、3=可独立解释、4=可尝试迁移。不填就不生成分数。近期明确的低自评参与今日复习排序；同课程同主题的后续自评覆盖旧值的排序作用，历史事件保留。已有周期复习的暂停/延后安排不会被这条路径重复拉回。

学习会话和事件保存在资料目录的 `study-agent.sqlite3`，类型为 `learning_session` / `learning_step`。续接只取最近四项、长答案返回节选及字符数；每项保留证据ID，来源改版或停用会提示重取。写入用 revision 防止多个对话互相覆盖，用 request_id 防重试重复。学生纠正答案时追加新记录，不改原文。

这些记录是学习过程与学生自报，不是已核验知识、自动判分或考试成绩。当前会话不会自动建立周期提醒或发送手机通知，避免和学习助手的调度重复。暂停后需要学生明确要求继续。

## 文献怎样参与核对

通用论文查 [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)，神经科学等生命科学主题查 [Europe PMC](https://dev.europepmc.org/RestfulWebService)。另有少量公开教材入口，例如 Wisconsin 的 [OSTEP](https://pages.cs.wisc.edu/~remzi/OSTEP/)。检索服务提供资料线索，本身不替我们判断结论正确。

检索只发送概念词，不把整段转写、文件路径或学生身份放进查询。缓存有效期为 24 小时，一次最多读两份候选；查不到正文时留下书目信息并说明缺口，不拿标题当证据。当前自动读取的论文内容主要是索引提供的摘要；教材读取也有页数和大小上限，不宣称通读整本书。

读取教材时传入文内检索词 `query`，工具就在本机从这份资料中选出最多三段完整片段。已经返回的原文直接用于对照，避免逐页取回再重复阅读。文内检索词不发给公开检索站。片段有页码和固定 ID；本次未匹配不等于整份资料没有讨论。

主 agent 先找课堂原话，再按同一个主张、同一组前提比较。回答区分“一致”“条件不同”“存在冲突”“证据不足”，给出原句、位置和来源。课程要求只能由课堂或老师提供的材料说明，外部论文不能推导考试范围。

出现实质分歧且宿主提供子 agent 时，最多增加一名复核者：只检查遗漏条件、摘要越界、引文支持度与重复来源。交接问题、争议点和至多六个证据 ID，不复制全部课程。普通查出处、排复习不启用团队；多名模型同意也不是事实证明。

同一 DOI 的转载、同一课时的学校字幕和本地转写不算独立证据。更正/撤稿提示会阻止该候选被直接当作支持材料，但这不是完整的撤稿核验服务。原始字幕不被改写，研究结果不会自动成为已确认知识。

## 资料库和动态记忆

课时位置、字幕版本、作答反馈与任务期限用 MCP 实时查。WorkBuddy 资料库适合放选定教材或可审阅产物，不能取代实时状态。需要静态快照时显式导出一门课：

```powershell
.\.venv\Scripts\python.exe scripts\prepare_workbuddy.py --export-course "操作系统"
```

输出 Markdown、`evidence.jsonl` 和 `manifest.json`，保留来源 ID、版本、页码或时间。不会自动上传；已有快照不会无提示覆盖。静态材料更新后，回答前仍需通过 MCP 检查当前版本。周期复习继续用学习助手的调度器，避免两边重复通知。

## 平台依据

采用官方 [MCP + Skill](https://open.workbuddy.cn/docs/connector) 接入方式，工具由本地 stdio 进程提供，不把课堂服务暴露到公网。技能格式见[官方说明](https://open.workbuddy.cn/docs/skill)。若之后部署固定角色团队，按[专家团规范](https://open.workbuddy.cn/docs/expert-team)配置，并以实际客户端工具权限为准。

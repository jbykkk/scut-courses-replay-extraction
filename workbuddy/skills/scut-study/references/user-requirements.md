# 用户需求台账

更新：2026-11-03。来源为本项目对话中的用户明确要求及后续修正；这是需求记录，不是功能完成声明。新要求若与旧要求有冲突，先区分场景，再按最近明确意见更新，不静默删除旧需求。

## 产品与日常使用

| ID | 用户要求 | 可观察的验收结果 |
| --- | --- | --- |
| UX-01 | Edge优先调试，同时兼容Chrome；安装和日常启动要普通人能理解 | 从一个明确入口启动、连接和打开工作台；需要百步梯登录时带用户到正确登录页 |
| UX-02 | 关闭面板不结束录音；最小化、重新打开详情都不应重启会话 | 关闭再打开仍为同一会话，字幕与分析状态连续，只有明确结束才停止 |
| UX-03 | 连接状态、模型就绪、是否存在录音任务分别准确显示 | 不出现“本地已连接”和“服务未启动”互相矛盾；启动无需概率性反复点击CMD |
| UX-04 | 交互从一件小事开始，逐步获取课表、要求和学习反馈 | 不要求首次填完全部信息；能用对话或一句任务进入实际工作 |
| UX-05 | UI克制、现代、整洁，适当动画；图标纤细、温柔、多彩、有颜料感 | 无不受控跳动/闪烁；移动端小尺寸也不拥挤、粗糙或塑料感强 |

## 采集、分析与课程记录

| ID | 用户要求 | 可观察的验收结果 |
| --- | --- | --- |
| CAP-01 | 多节直播、直播与回放、多个回放可同时提交转写分析 | 每课独立会话与进度，资源调度可排队但不互相串课；即时提醒不中断 |
| CAP-02 | 使用本地ASR，支持模型选择；抑制异常循环而保留正常重复讲解 | 异常有可解释状态，不能默默保存海量重复字；没有语音与识别失败分别处理 |
| CAP-03 | 学校字幕、本地转写、局部结果合成同一课时 | 同源结果被完整覆盖时去重/替换；可删除/恢复；不会多次导入造成课内混乱 |
| CAP-04 | 回放/目录导入可靠，标签页变化不导致no-tab或导入丢失 | 入队后任务可见且持久；旧tab失效可恢复定位；不能显示成功却找不到任务 |
| NOTE-01 | 所有保存字幕默认自动生成笔记，分析使用上下文 | 不要求逐课点击；长课有完整分段与合并，失败可继续而非只留碎片疑似事项 |
| NOTE-02 | 作业与所有重要事项完整分类，按新到旧显示并定位到课内时间段 | 不以是否包含“作业”二字决定是否展示；有类别、原句、课时、起止时间与回看入口 |
| NOTE-03 | 模型/Key可配置，Key本地持久且与代码分离 | 可知道已保存Key是否检测到/连接有效；不把Key、口令、Cookie提交Git或导出日志 |
| NOTE-04 | 处理失败要区分ASR、文件、连接、模型返回、截断等原因 | 零字幕、字幕已保存但笔记失败、整理完成等状态互不混淆；列表与详情一致 |

## Agent、资料与学习

| ID | 用户要求 | 可观察的验收结果 |
| --- | --- | --- |
| AG-01 | 能直接说“处理某课尚未处理的所有课时”或提供文件/文件夹路径 | 解析成可观察、可恢复的批任务，确认已处理项不会重复；只读取授权材料范围 |
| AG-02 | 音频、字幕、课堂截图/板书、PPT、教材和题目文件联合理解 | 给出课时—视频时刻—资料页/题号的联系；缺少画面时明确说未核实 |
| AG-03 | 识别错误、片面知识不得直接变成可信知识 | 原文、纠错建议、跨来源冲突、已确认要求、模型解释分开；外部知识核对有出处与条件 |
| AG-04 | 跨课时问答带老师原句、解释、课时与时间，可直接回看 | 能回答“老师在哪讲过条件变量”这类真实检索问题，而不是仅给常识回答 |
| AG-05 | 结合薄弱点、期限、难度、可用时间生成学习与补课方案 | 可回答“今晚只有30分钟先学什么”；该预算场景不能被当作所有复习的默认压缩路线 |
| AG-06 | 周期复习、出题、反馈、知识深度串联和兴趣研究 | 根据作答调整，不把读过当掌握；可延后/暂停，普通复习与课堂急讯区分 |
| AG-07 | 可生成MD/PDF等复习、题目资料并管理来源与记忆 | 文件可打开、有版本和来源；生成资料不自动升级为已确认事实；记忆可以修正 |
| AG-08 | 可看清系统提示词、工具调用、检索、循环与记忆的运作 | 可视化显示实际执行过程与失败原因；减少无谓token、复用提取与缓存，避免重复全文发送 |
| AG-09 | DeepSeek为主要模型，也可接入其他模型；工具与循环按场景特化 | 提示词、工具协议、状态、预算和证据校验可检查；不用堆SDK/Agent数量代替任务效果 |
| AG-10 | WorkBuddy接入需真实可用，合理使用知识库/工作流/多Agent等能力 | 在客户端/平台实际走通场景与链接；已写适配文件不等于平台验收完成 |
| AG-11 | 微信/QQ、日历等连接作为扩展，而非核心学习流程的前提 | 有接口证据和实际送达/同步测试后才称已接入；核心功能不依赖这些可选渠道 |

## 内容与教学方式

| ID | 用户要求 | 可观察的验收结果 |
| --- | --- | --- |
| EDU-01 | 从零讲原理，按主题整合跨课时，而不强行一课对应一PPT | 有前置解释、推导、完整例子、练习；教师强调、研究请求、学生汇报分别标注 |
| EDU-02 | 重点、难点、可能考、建议研究的内容要展开 | 保留教师条件/不确定性；研究题不因不是正式作业而遗漏；不宣称“必考/不考” |
| EDU-03 | 课件与考试英文，概念引入时就有英文 | 小节标题、首次解释、定义旁出现英文；不是仅在最后加一个对照表；中英题干与答案可对应 |
| EDU-04 | 知识串联与理解深度不足，需要改进讲法 | 说明模型为何出现、保留/丢弃什么、与前后章怎样连接；有反事实、变式题和两个综合情境 |
| EDU-05 | 作图要求须区分PPT原图、课堂/板书、讲义自编和考试要求 | 在相关段落、题目和图旁就地标明出处、发言者判断、是否见画面、原话强度与未知项 |
| EDU-06 | 不确定教师究竟在板书还是随口提及，要明说 | “字幕说画图”不写成“已看见老师画图”；学生展示不冒充教师；无证据不补造考核承诺 |
| EDU-07 | 还有充足时间时按完整理解和多轮回顾学习 | 当前神经科学包默认完整学习；速查为辅助，只有明确选择预算时才进入短时安排 |
| EDU-09 | 英文考试要能认出概念的不同名称，且区分认名与理解失败 | 同课程、有原文支持的别名辅助检索与变式提问；歧义不合并，不把相关概念当同义词，词表不等于完整考纲 |
| EDU-10 | 例题需要公式依据、中间过程与独立检查；原资料有错也要识别 | 布尔式穷举、数值复算、HDL按实际工具区分编译/仿真/综合；题面和答案冲突并列，不静默选一边 |
| EDU-08 | 文案自然直接，减少AI套话与功能堆砌 | 解释具体问题和因果，不用流程口号掩盖知识缺口；交互先给可完成的一步 |

## 使用与更新规则

本次项目所有者已明确授权当前项目相关DeepSeek处理与复核，不反复询问同一范围的调用；凭据仍与代码分离。这是当前所有者的会话记录，不对其他安装者生效，也不扩展到其他服务、公开发布或绕过当前执行环境的审核。

- 产品能力是否已完成，另看`ACCEPTANCE.md`与实际测试证据。本台账不继承旧文档里的“已实现”作为本轮验证结果。
- 教学资料生成与作图证据规程见`TEACHING_EVIDENCE.md`。本机课程包有更具体的课时、页码与来源状态，不复制其私有正文到公开项目文档。
- 本台账把研究、教学、通知和可选渠道分开是为了追踪，不规定用户界面必须分成这些板块。
- 用户后续纠正应更新对应ID与验收条件；不要用新摘要抹掉限定条件。例如：预算30分钟的计划需求仍有效，但不能默认把有充足时间的复习压成30分钟。

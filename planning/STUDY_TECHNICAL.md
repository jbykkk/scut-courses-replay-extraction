# 学习工作台：实现说明

## 数据流

```mermaid
flowchart LR
    A[学校字幕 / 本地转写] --> E[带来源的证据片段]
    B[PDF / PPTX / DOCX] --> E
    C[屏幕截图索引] --> V[视觉识别与对齐：后续]
    V --> E
    E --> R[按课程检索]
    R --> L[有预算的分析循环]
    L --> Q[结构与引文校验]
    Q --> P[待核对的结论 / 提案]
    P --> U[学生确认]
    U --> T[任务与课程要求]
    D[确认后的课表] --> S[按容量排程]
    T --> S
    S --> I[计划草稿 → 确认 → ICS]
    Q --> X[练习 → 自评 → 下次复习]
```

## 模块

`assistant_service/study_agent/` 不接管音频线程。通过现有 FastAPI 的 `/api/study/` 接入，沿用本地请求的 Host、Origin 和连接口令检查。网页入口为 `study.html`。

- `storage.py`：独立 SQLite 库 `study-agent.sqlite3`。源内容按指纹去重，原位置更新时使旧版本退出新检索，历史引文保留。
- `ingest.py`：只读注册资料目录；跳过虚拟环境、代码依赖、隐藏配置与疑似凭证文件。保留页码、幻灯片号或字幕时间。提取不到文字返回失败，不能把扫描版 PDF 标记为成功。
- `timetable.py`：按学校导出 PDF 的九列表格读取，保留周次。只是候选课表，必须确认学期与节次时间后才能展开。
- `reasoner.py`：自定义 HTTP 模型适配；自动工具包括限定当前课程的检索与相邻段落展开。每轮最多 3 次模型调用，每次最多 3500 输出 token；图片输入先用一次视觉读取，随后最多两次核对调用。文本调用 30 秒超时、图片读取 35 秒超时。来源最多 12 段，超过上下文预算不再追加。JSON 与逐字引文校验失败时限次修复，不能通过则不保存新提案。
- `planner.py`：按确认的耗时上限、截止日期、难度和空闲时段安排，不用模型生成时间表。没有截止日期就没有到期事实。
- `api.py`：资料、提案、计划、练习和课表的状态接口。学习模型调用限为同时 1 个，避免新功能抢占课堂即时事项分析的请求。
- `extension/visual-evidence.js`：只读当前课时 DOM 的 `.ppt_wrap` / `.ppt_time` / `img[data-src]`；校验学校域名、课时和 PPT 图片路径；不导出学校 Cookie。

## 四种记忆不要混用

| 记录 | 谁能写 | 如何使用 |
| --- | --- | --- |
| 原始证据 | 资料导入、课堂同步 | 可引用，不由模型覆盖 |
| 课程要求 | 学生确认后的提案 | 可作为后续问答的上下文 |
| 学习情况 | 学生的完成记录和练习自评 | 用于调整建议，明确属于自报 |
| 模型提案 | 经校验的分析输出 | 等待确认，不自动变成事实或通知 |

引文先做逐字校验，随后另做一次最多 25 秒的出处支持度检查，检查必要条件、否定和推导是否有依据。依据不足或冲突的解释退出正文，保留疑问；未通过检查的参考答案不保存，检查服务失败时不生成复习文件。该检查仍使用语言模型，并不是独立事实认证。纠错提案至少引用两个不同来源，且不能仅由两份相关的转写互相证明；原字幕不被改写。

## 模型配置

不配置新文件时，直接复用已有 DeepSeek Key 和所选模型。网页会显示模型配置是否存在；这不等同于已验证服务连通。

其他兼容服务可在本地 `.local/study-providers.json` 设置。该文件不进仓库，密钥存环境变量，示例见 `config-examples/study-providers.example.json`。本机推理服务可用 HTTP，远程服务要求 HTTPS。默认不跟随重定向；只有精确的 DeepSeek 官方域名可以复用原 Key。

版本化提示词在 `prompts/study-v1.txt`。工具返回的是非可信来源数据，不能授权读文件、调用外部接口或改变工具集合。执行日志保存调用步骤和引用，不记录密钥和模型内部推理。

## 安装与运行

```powershell
uv sync --extra asr --extra study
```

沿用现有启动方式，打开 `http://127.0.0.1:8765/study.html`，或者从扩展的“课程笔记”导航进入“学习工作台”。从浏览器扩展打开时可以读取学校页的 PPT 索引；普通本地网页没有浏览器标签页权限。

直接输入问题、拖入课件或粘贴截图即可开始。课程不明确时只追问课程名；连续追问会携带同门课的最近上下文。任务、资料和课表放在“资料与安排”中按需打开。扫描 PDF 仍需先提取关键页面为图片；复杂公式和手写图像必须回查原图。

## 平台接入边界

WorkBuddy 官方支持 MCP 连接器与 CLI 连接器，本地 MCP 可使用 stdio。本轮提供 `python -m assistant_service.study_agent.mcp --data-dir <本地数据目录>`，暴露课程列表、课程检索、原文回查和已确认任务四个只读工具。配置示例在 `config-examples/workbuddy-mcp.example.json`。连接后，平台可读取工具返回的课程片段，因此只应连接学生选择使用的平台工作空间。确认任务、日历写入和通知发送仍留在工作台。参赛发布需另行完成真实的平台部署与访问验证。

参考：[WorkBuddy 连接器规范](https://open.workbuddy.cn/docs/connector)、[MCP stdio 规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。本轮完成本地协议测试，尚未在 WorkBuddy 账号中联调，也未提交或安装市场连接器。

图片通过 Chat Completions 的 image_url 内容块发送。DeepSeek Flash 默认启用视觉能力；其他模型需显式配置 supports_images。图片先识读为带原图链接、标明未核对的证据，再与课件和课堂上下文核对。不得把视觉识读结果标成已校验的原文。参考：[DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/)。

## 连续对话与复习事件

- `dialogue.py` 保存消息、附件引用与运行状态；同一请求 ID 不重复调用模型。按课程隔离最近六轮线索：最近两轮保留压缩回答，更早的轮次保留问题；整体限制在约 2000 字符，换课时不混入上一门课的回答。
- `attachments.py` 接收学生选中的文档和图片，不要求先填写文件夹路径。附件只存在 `.local/study-uploads`，发送消息时才将相关文字或所选图片交给模型。单文件 12 MB，每轮最多四份，总计 24 MB。
- `reviews.py` 保存复习主题、到期时间、反馈和周期。手机发送沿用原有加密 outbox；重启后继续，暂停/推迟会使旧通知失效。22:00—08:00 不发送复习通知，每天最多两条；不会阻塞点名等课堂提醒。电脑休眠或本地服务停止时不能发送。
- 普通回答先展示两个关键点，其余内容可展开。知识串联必须有两处不同证据；深入总结围绕核心问题、推导关系和适用边界。
- 要求录入采用一问一步：先确认事项，再核对截止，最后估计用时；不知道的日期可留空，不好估计的大任务可以继续拆分。

当前没有接入微信或 QQ。对话接口与渠道无关，后续可以复用相同消息、提案和复习状态，避免每个渠道各自保存一份进度。当前跨课程的自动知识图谱、客观作答评分、学习计划自动重排仍未实现。

## 0.11 的执行工具

`operations.py` 注册六个带严格参数结构的操作：本地读取、缺失回放处理、资料导出、外部参考、课堂与题目对照、复习偏好。显式路径和批量请求先用确定规则解析；其余操作交给原生 function calling 选择。模型只提出工具及参数，执行器重新检查权限范围和字面路径。资料内容不能触发执行工具，没有任意 shell 或任意写文件工具。协议参考 [DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)。

操作以请求 ID 去重，写入 SQLite；逐文件、逐课时记录进度。服务重启后恢复队列，重试保留成功步骤。取消停止后续步骤，已经进入原有音频管线的课时仍可在课堂记录里管理。后台资料生成持有单个学习模型槽位；明确的排队请求可以继续提交，课堂即时分析沿用原来的线程与优先级。

浏览器每 30 秒领取回放任务，使用 90 秒租约避免两个浏览器同时提交。必须在已登录、课程名称与 course_id 匹配的学校页操作；每轮最多提交六节、目录最多 1000 节。已有完整笔记跳过，有字幕的仅补分析，失败记录走原重试入口。凭据不通过学校页面传给本地代理，Cookie 不导出。批次状态等待原有转写与笔记任务实际完成。

文件夹一次最多读取 300 份支持的文档，忽略代码依赖、隐藏配置和疑似密钥；图片路径必须是明确给出的单文件，识读需模型支持视觉。导出器只写本地专用 `study-exports` 目录。PDF 用 ReportLab 排版，Markdown 保留引用；习题的参考答案另页展示。

## 来源、记忆与复习

资料策略按课程与原位置保存，更新文件版本不会绕过已停用的策略。来源分为教材、题目、课件、转写、外部资料等；“选作参考”是学生的来源选择，不是权威认证。字幕和识图不能直接升格为可靠参考。确认知识需要出处检查和学生操作；每次回答最多取五条相关记忆，仍须回读原始证据。来源更新后旧记忆失效，旧引用可追溯，撤回不删除原件。

复习按逾期天数、上次的理解缺口和本课已确认任务排序，每天默认 15 分钟。模型反馈只对照有效原文，不以参考答案措辞判对错；只有字幕依据时不判分。反馈与自评取保守值调整间隔，并选择基础辨析、应用或知识联系的题型。临近确认截止时间会提前复习，避开已确认课表；没有客观掌握度或考试分数的宣称。

`knowledge.py` 将同课字幕与本地题目做词项关联，保留时间与页码；仅挂接同一课时、相近时间的学校截图。最多读取两张实际截图交给视觉模型；没有图像能力或无法读取时，只保留链接并说明限制。所有自动对应均标为候选，不用模糊的词项重合假装题号匹配成功。

外部参考只发短概念词给 [MediaWiki TextExtracts](https://www.mediawiki.org/wiki/Extension:TextExtracts)，或读取明确提供的允许域名 HTTPS 链接。网页限 6 MB，PDF 最多 30 页；不跟随跳转、不读取内网，保留检索时间与 URL。VPN 的基准地址映射只允许固定公开出版站点，仍校验 TLS 域名。可在本地 `.local/study-network.json` 配置 `reference_proxy` 为本机代理，文件不入库；网络失败不冒充查证完成。外部资料与课件也可能有版本或语义冲突，需人工核对。

手机 0.11 增加本机搜索、分类、实际发生时间排序、已读状态及复习原因。已读不会代表学习完成；没有新增远程文件读取、自动答题或手机直接控制电脑的权限。


## 运行记录与请求开销（0.12）

学习页的“运行详情”使用 `/api/study/runtime`、`/runtime/{id}?after={seq}` 和 `/runtime/catalog`。仍需本地配对口令，学校页面不能读取。约 1.7 秒刷新一次，只在查看器打开且页面可见时请求；切换执行记录会丢弃旧请求的迟到响应，新增事件不重建已经展开的提示词。

`assistant_service/telemetry.py` 通过 ContextVar 将同一轮的检索、模型、工具、核对事件串在一起。后台任务另建记录并保留发起对话的关联；浏览器批次跨请求记录每节课的进展。课堂笔记与实时分析也显示课程、课时及实际模型请求。记录的是可观察的输入输出和状态，不是模型的隐藏思维。

主提示词在 `study_agent/prompts/study-v2.txt`。任务专用规则在 `prompt_catalog.py`；工具选择、出处检查、图片读取、练习反馈、课堂分析、整课事项分别有独立文本文件。查看器同时提供文件位置、内容指纹和严格工具参数结构。修改模板后重启本地服务生效；既有执行快照保持原样。

优化的边界：

- 资料全文使用 FTS5 索引，中文按二字词项预分词；检索后重排候选，排除停用来源与历史版本。没有 FTS5 的环境回退原有检索。旧库启动时补建一次索引。
- 原文最多 24000 字符，按完整片段选入，超出预算的片段列入记录。相邻段和再次检索去重；后续模型仍可引用已读取的 ID。去掉段内冗余元数据，不改写原文。
- 确认要求、当前任务、学习状态与确认知识按问题选取；时间安排类问题保留近期任务上下文。确认知识仍需加载当前原文，失效、停用或被替代的条目不参与新回答。
- 稳定规则置于请求前缀，JSON 紧凑序列化；回答、图片、工具选择与核对分别控制输出预算。复用 HTTP 连接，课堂分析与学习问答保留各自并发控制。
- 出处核对缓存以模型服务、模型、核对规则、完整待检结论和所引原文内容为键；校验通过的检查结构才能入缓存。原文或规则变动后重新请求。最多 256 项、7 天，不缓存或伪造新的模型回答。
- 文档内容指纹未变时跳过重复解析；字幕未变时跳过重新分段。新的对话和运行结果只存原文 ID，避免每轮复制整份证据。已保存的用户原文与历史引用不删除。
- 运行记录在 `.local/agent-runtime.sqlite3`，长请求快照压缩存储；已完成记录保留最多 30 天、300 次。`study-agent.sqlite3` 保存资料与确认记忆。连接口令、API Key 与这些记录分开，认证头不写入日志；图片不复制 base64 到记录。
- token 用量来自模型响应，未返回时显示未知。缓存 tokens 是提供商报告的命中量，本地核对复用单独记录；字符预算与耗时不换算成虚构费用。参考 [DeepSeek 上下文缓存文档](https://api-docs.deepseek.com/guides/kv_cache/)。

覆盖的回归包括：运行中可读取事件、增量游标、并发隔离、敏感字段脱敏、API 鉴权、缓存失效、旧资料库补索引、来源排除、上下文去重、异步批次、页面切换竞态。查看器只读，没有通过它修改提示词、重放有副作用工具或导出含课程内容的运行快照。
